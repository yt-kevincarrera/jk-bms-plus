Qué cambia en toda la app

Una sola identidad por app, con tres ritmos de información: vistazo al conducir, recorrido visual para revisar un viaje y detalle técnico al diagnosticar. Los tres estilos cambian composición, instrumentos, tipografía y superficies; no son simples cambios de color.

Inicio·Batería → Celdas / Temperatura·Viajes·Salud·Ajustes → Sistema / Taller

Pasar de las seis pestañas actuales a cinco es una propuesta de arquitectura de información. Celdas y temperaturas siguen accesibles dentro de Batería. Viaje activo funciona como una tarea a pantalla completa con salida visible. Inspección conserva su flujo independiente; un pack ajeno nunca se convierte en tu batería.

Accesibilidad, tokens y traducción a Flutter

Android/Flutter: principios de Apple para jerarquía, claridad, feedback y accesibilidad, conservando controles Material. Objetivo de controles táctiles: 48 × 48 dp como mínimo; acciones de conducción de 56 dp. Cuerpo 16–17 sp, datos de conducción 80–128 sp, etiquetas 13–14 sp. Cifras tabulares, sin pesos finos. La maqueta compacta usa algunas leyendas de 11–12 px; no fija el tamaño final de Flutter.

Apariencia clara y oscura para cada identidad. El selector de esta propuesta sirve para comparar maquetas; en la app se seguirá la apariencia del sistema. Sin desenfoques detrás de lecturas ni animaciones continuas de instrumentos. Texto, icono y color acompañan cada alerta.

NavigationBar de cinco destinos; SegmentedButton para el detalle de batería; ListTile y SwitchListTile para ajustes. Respetar MediaQuery.textScaler, SafeArea y LayoutBuilder. Reorganizar las métricas a una columna con texto grande; no encoger el texto para forzarlo dentro de tarjetas.

Bahnschrift expresa instrumentación en estas maquetas si está instalada; Segoe UI es el fallback. Para publicar, se debe elegir y empaquetar una fuente con licencia adecuada o mantener cifras del sistema; el funcionamiento no dependerá de una fuente de Windows.

Alcance, evidencia y orden para implementarlo

Revisión basada en el código del checkout: theme.dart, home_shell.dart, las seis pestañas actuales, pantallas de conexión/viajes/ajustes/inspección y sus vistas secundarias. El tema define etiquetas de 10,5 px y texto tenue #5B6474; en la navegación ese color sobre #080A0F da aproximadamente 3,3:1, insuficiente para etiquetas pequeñas. Es evidencia de código; no es una evaluación del render actual en un teléfono.

Ahora: propuesta HTML autónoma, sin modificar Flutter, BLE, GPS, cálculos, persistencia o licencias. Ejemplos e informes ficticios, identificados como demo. No se activan pagos ni operaciones de escritura del BMS. Licencia sigue oculta si la función está desactivada; su vista se incluye únicamente para completar el diseño del flujo existente.

Después de elegir dirección: 1) tokens y componentes accesibles; 2) navegación y estados de conexión; 3) inicio, carga y viaje; 4) diagnóstico, históricos e informes; 5) ajustes y taller; 6) verificación de flujos afectados, análisis y build. La aceptación visual requiere capturas comparables en Android, texto ampliado, modo claro/oscuro y evaluación exterior. Este HTML no prueba recepción BLE, precisión del rango ni ejecución con pantalla apagada.

Compromisos: Horizonte ofrece el mejor equilibrio entre personalidad y lectura; Roadbook favorece el día y deja menos sensación de panel deportivo; Apex tiene más carácter deportivo, pero su densidad exige mayor cuidado al ampliar texto. Se elimina decoración que compita con el dato: fotos de motos, carbono falso, medidores sin unidades y tarjetas dentro de tarjetas.
